# 心理港湾 · 项目详细介绍

> 版本：对应 `psych-loop/phase7-production`（PR #7）
> 面向读者：评审、指导老师、接手开发的同学、未来试点的运维

---

## 1. 这是什么

**心理港湾（PsyQA）** 是一套面向高校学生的心理支持平台。它同时提供两层服务：

- **自由层**——随时开口的对话空间（倾诉、问答、阅读），不预设任务；
- **结构化层**——DeepTutor 式「心理闭环」工作区：签到 → 计划 → 微行动 → 复盘 → 周总结，把模糊的自我关怀拆成可以落地的最小动作。

两层不互斥：对话是自由层，闭环是轨道层；**危机命中时闭环随时暂停，强制切到安全路径**。

产品定位是辅助支持，不是诊疗工具：不做精神疾病诊断，不建议停药/换药/开药，高风险时只做一件事——稳住安全、把人引向真实求助通道。

## 2. 用户角色

| 角色 | 入口 | 能做什么 |
|---|---|---|
| 学生 | 学生端 Web（CRA，`localhost:3000`） | 对话倾诉、闭环工作区、情绪记录、训练模块、漂流瓶、Wiki 阅读 |
| 辅导员 | 教师端 | 院系级聚合看板（情绪天气 + 闭环使用度），k-匿名保护 |

## 3. 心理闭环：产品核心设计

### 3.1 七环节与现状映射

参考 DeepTutor「诊断-计划-执行-反馈」学习闭环，映射到心理支持场景：

| 环节 | 实现 | 关键设计 |
|---|---|---|
| 签到 | `wellbeing_checkins` + `POST /api/loop/checkin` | 心情/压力/睡眠/能量/一件事；**`skipped:true` 是合法打卡**——跳过本身被尊重，不施压 |
| 计划 | `support_plans` + `plan_actions` | 一个周目标 + ≤21 个微行动（每天 1–3 件小事）；`adjustPlan` 旧计划归档、新计划激活，调整链留痕（`source: adjust:<id>`） |
| 微行动 | `practice_logs` / 行动状态 | `done`/`partial`/`skipped` 三态都合法，**不评判、不催办** |
| 复盘 | `reflections` | 晚间三行（做了什么/感受/明天）与周复盘（有效/无效/调整） |
| 周总结 | `progress_snapshots` | 编排器聚合一周数据生成文本总结，幂等 upsert 落库；过期 active 计划自动收口 `completed` |
| 记忆 | 沿用既有 L1/L2/L3 蒸馏 | `update_memory` 只写**用户确认过的项**，工具层强制 |
| 危机预案 | `safety_plans` | 用户平时自写的应急卡（可联系人/可做之事/预警信号），危机时自动带出 |

### 3.2 闭环编排器（`loopOrchestrator.ts`）

- `GET /api/loop/today`：今日状态机——是否已签到/有计划/今日行动清单/晚间复盘是否完成，外加**一句可选的下一步**（"想签个到吗？…跳过也算数"）；
- `GET /api/loop/summary`：周聚合 → 快照落库 + 人话总结，明确标注"只是自我觉察，不是诊断"。

### 3.3 闭环 Agent 与安全执行器

`loopAgentTools.ts`（9 个确定性工具）+ `loopRuntime.ts`（有界执行器）：

- 工具面：`safety_check`、`search_psych_knowledge`、`get_recent_signals`、`create_support_plan`、`adjust_plan`、`log_micro_action`、`log_reflection`、`suggest_practice`、`update_memory`；
- **不变量**：`safety_check` 永远是第一个执行的工具；`riskLevel` 为 high/critical 时除 `safety_check` 外所有工具（尤其一切写工具）全部阻断，返回固定安全模板（热线 + 用户应急预案），不深挖创伤；
- 有界执行：最多 `LOOP_MAX_STEPS=5` 步、整体 `LOOP_TIME_BUDGET_MS=3000` 预算；
- 决策说明：工具层**暂不注入** ReAct `COUNSEL_TOOL_DEFS`——那会改咨询 prompt，必须跑 `eval:ragas` 评测回归，而评测依赖的外部服务恢复前不动。

### 3.4 信号进蒸馏层

`collectUserSignals` 从 5 类扩到 8 类，闭环行为成为 L2/L3 画像的蒸馏材料：

| 信号 | 降噪规则 |
|---|---|
| `checkin` | `skipped` 打卡不进信号（尊重跳过即隐私） |
| `plan` | 只取 `done`/`partial`，pending/skipped 不产噪声 |
| `reflection` | 全部进入——"什么有用/没用"是高价值信号 |

## 4. 安全体系（红线）

| 机制 | 实现 |
|---|---|
| 风险分级 | 固定 `low \| medium \| high \| critical`，无 `risk_red` 等私造标识 |
| 危机路由 | 规则层命中危机或 high/critical → 强制安全路径，普通问答不得捷径绕过 |
| 热线 | `400-161-9995`，**单一出处** `server/src/services/psych/emotionService.ts`（`assessRisk().hotline`），禁止硬编码第二处 |
| 高危回复 | 固定安全模板：稳住安全 → 联系可信的人/校心理中心 → 热线；不深挖创伤细节 |
| 应急预案 | `safety_plans` 表存用户自写应急卡，安全回复中优先带出 |
| 隐私 | 教师端只出 k-匿名聚合（<5 人组 `metrics=null` 抑制，并入 `merged-small`），永不返回个体数据 |
| 边界话术 | 总结/报告里明确"自我觉察，不是诊断"；产品是辅助支持非治疗 |

安全回归：`npm run eval:safety`（7/7 路由检查）+ `loopAgentTools.test.ts`（high/critical 下写工具阻断断言）。

## 5. 技术架构

```
React (CRA) ──► Express/TS API ──► SQLite (better-sqlite3, WAL)
     │                │
     │                ├──► Qdrant(6333) + bge-m3(8091)  向量检索/重排
     │                └──► LLM：GLM(智谱) → Ollama → 规则兜底(fallback)
```

- **问答编排**：`server/src/services/question/answerOrchestrator.ts`；检索命中文档 id 全链路透传到回答与界面
- **LLM**：`llmClient.ts` 统一入口；GLM 优先、Ollama 备选、不可达时规则兜底（UI 有降级横幅）
- **闭环模块**：`server/src/services/loop/`（checkinService / supportPlanService / reflectionService / resourceService / loopAgentTools / loopRuntime / loopOrchestrator）
- **前端**：`client/src/student/LoopWorkspace.tsx`（闭环工作区）+ `api/loop.ts`；主题令牌在 `client/src/theme.css`
- **学校端聚合**：`schoolWeatherService`（情绪）+ `schoolLoopWeatherService`（闭环使用度），同一 k-匿名模式

## 6. 数据模型

版本化迁移器（`meta.schema_version`）管理演进；v3 新增闭环 8 表：

| 表 | 用途 |
|---|---|
| `wellbeing_checkins` | 每日签到（含 skipped 语义） |
| `support_plans` | 周计划（active/completed，调整链 source 字段） |
| `plan_actions` | 微行动（三态 + day 归属） |
| `practice_logs` | 练习记录 |
| `reflections` | 晚间/周复盘 |
| `progress_snapshots` | 周总结快照（幂等 upsert） |
| `safety_plans` | 用户应急卡（contacts/coping/signals） |
| `resource_items` | 心理技能/自助方法/校内资源（counselor+admin 维护） |

另有 `revoked_sessions`（v2，会话撤销）。SQLite 备份/恢复：`npm run db:backup` / `db:restore`（在线 backup API，活动 WAL 拒覆盖，恢复前自动留 .pre-restore 副本）。

## 8. 工程实践

- **CI**（`.github/workflows/ci.yml`）：全分支触发；`build`（tsc+单测+前端构建）、`docker`（多阶段镜像构建）双 job；`npm audit --omit=dev` 高危门禁；跟踪数据检查（运行时文件不入库）
- **Docker**：alpine 三阶段（deps/build/runtime）；better-sqlite3 无 musl 预编译 → deps+build 装 `python3 make g++`；`client/.npmrc`（legacy-peer-deps，解 react-scripts@5 vs typescript@5 冲突）显式 COPY 进镜像；运行时数据全部走卷/环境注入
- **安全 headers**：全响应 CSP（script 仅 self）、HSTS 生产门控
- **数据库**：WAL + 版本化迁移；禁止手改既有 `CREATE TABLE` 基线，新表一律加 migration 条目
- **已知 flake**：Windows 计时器 ~15ms 粒度 → 所有 `ORDER BY created_at` 均加 `id DESC` 兜底

## 10. 开发指南

```bash
cd PsyQA
npm run install:all   # 安装
npm run dev           # 前后端并行 → http://localhost:3000/login
npm run check         # 启动前自检
npm run test          # 单测
```

规则与约定：

- `.cursor/rules/psyqa.md` 编号条目是工程权威（一次改动 ≤300 行、改 prompt/检索必跑 eval:ragas 等）
- `.cursor/rules/psyqa-ethics.mdc` 伦理红线（不诊断/危机路径不可跳过/热线口径）
- `AGENTS.md` 目录与命令速查
- 界面改先看 `client/src/theme.css` 令牌；运行时数据（db、向量库、账号、历史）永不提交
