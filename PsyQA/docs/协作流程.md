# 协作流程

> 给项目新同学的 git / PR 上手说明。规则一句话：**main 只接受 PR 合并，任何人不直推**。

## 一次性准备

```bash
# 1. 装 git：https://git-scm.com/download/win
#    不想用命令行可以装 GitHub Desktop（图形界面，流程一样）
# 2. 克隆仓库到固定目录
git clone https://github.com/pengjianhao-work/psyql.git
cd psyql
```

## 每次改代码（5 步）

```bash
# 1. 先同步最新 main，再切自己的分支
git checkout main
git pull
git checkout -b feat/功能名        # 例：feat/screening-panel

# 2. 改代码

# 3. 提交：一个功能一个 commit，message 一句话说清做了什么
git add <改动的文件>
git commit -m "feat: 症状自评面板（PHQ-9/GAD-7）"

# 4. 推送
git push -u origin feat/功能名

# 5. 开 PR：点终端输出的链接，或仓库页 Compare & pull request，base 选 main
```

commit message 前缀：`feat:` 新功能、`fix:` 修 bug、`docs:` 文档、`refactor:` 重构、`ci:` 流水线。

## 红线（违反会被要求返工）

- ❌ **不要用 GitHub 网页上传整文件**。网页上传看不到基线差异，拿旧文件覆盖会直接抹掉别人已合入的功能（实际发生过：一次 zip 覆盖会丢掉 MoodCheckinCard、wiki 检索、回答消毒器等）。
- ❌ 不要直接 `git push` 到 `main`。
- ❌ 不要把运行时数据提交进库：数据库 `*.db*`、`server/data/`、`vector_db`、账号文件、`.env`。
- ✅ 改之前先 `git pull`，确认基线最新。
- ✅ PR 描述写清楚做了什么、怎么验证的。

## 本仓库特有的约定

1. **改回答提示词、检索或重排参数前先说一声**——按 `.cursor/rules/psyqa.md` 第 3 条，这类改动必须跑 `npm run eval:ragas` 回归（需要 bge-m3 :8091、Qdrant :6333、可用 LLM），评测服务不可用时暂缓合并。
2. **心理安全红线**（`.cursor/rules/psyqa-ethics.mdc`）：不诊断、不代填量表分、危机路径不可绕过；热线 `400-161-9995` 以 `server/src/services/psych/emotionService.ts` 为准，新增求助资源需为可核实的官方渠道。
3. 危机/high/critical 相关改动先过 `.cursor/skills/safety-review` 清单。
4. 界面改先看 `client/src/theme.css` 已有令牌，不另起配色。

## 遇到问题

- GitHub 网页打不开 / 500：平台侧故障，刷新或等几分钟，`git` 命令行一般不受影响（两条链路）。
- 推送被拒（non-fast-forward）：先 `git pull --rebase` 再推；不要 `push -f` 公共分支。
- 不确定怎么合：把分支推上去（哪怕没做完），在群里说一声让同学帮看。
